# Админ-панель DevUp

Вход: `/admin/login`. Ссылки с публичного сайта для обычных посетителей нет. Создай менеджера командой из `backend`:

```powershell
./.venv/Scripts/python.exe manage.py create-manager your_login your-email@example.com
```

Пароль вводится скрыто, минимум 8 символов. Код приходит на почту менеджера через уже настроенный SMTP. Почта менеджера не возвращается в админском профиле. Клиентский пароль по-прежнему требует минимум 10 символов; это существующее соглашение сохранено.

Сброс пароля только через CLI:

```powershell
./.venv/Scripts/python.exe manage.py reset-manager-password your_login
```

Сброс отзывает все сессии и коды менеджера. Менеджеры не входят через публичную форму. Админская cookie `devup_admin` имеет Path=/api, httpOnly, SameSite=Strict; сессия живёт 30 минут простоя и максимум 8 часов. Клиентская сессия хранится отдельно.

## Разделы

- Заявки: статус, поиск по номеру/контакту, свободные заявки, страницы по 20, полная карточка, история с автором, внутренний комментарий, новый одноразово показываемый код привязки, ручная привязка клиента.
- Пользователи: поиск по почте, подтверждение, даты, количество и список заявок. Менеджеров здесь нет. Свободную заявку можно выбрать и привязать с подтверждением.
- Услуги: четыре фиксированные услуги, редактирование текста/пунктов и цены. Пустая цена означает «по запросу». Публичная страница читает API.
- Портфолио: реальные работы без демонстрационных сидов, черновики и публикация, порядок работ и картинок, одна обложка, подписи, загрузка с ошибками отдельных файлов, подтверждение удаления и предупреждение о несохранённых изменениях.

«Открыть сайт» открывает публичную часть. Админ-полоса показывается после проверки сессии, только если установлен локальный флаг входа. Для обычного посетителя дополнительных запросов к админскому API нет. Переключатель черновиков хранится в sessionStorage. Он не даёт доступа без админской сессии.

## Медиа

Новые настройки в `.env.example`: MEDIA_ROOT, MEDIA_URL_PREFIX, FILE_STORAGE_BACKEND, MAX_UPLOAD_BYTES, ADMIN_SESSION_IDLE_MINUTES, ADMIN_SESSION_MAX_HOURS. По умолчанию файлы лежат в `devup-app/media`, URL начинается с `/media`.

Разрешены статичные PNG, JPEG, WebP по содержимому, до 5 МиБ и 8000×8000. Сервер удаляет метаданные, учитывает EXIF-поворот, создаёт WebP до 1600 пикселей по длинной стороне и копию шириной до 640 без увеличения. Имена случайные; исходное имя не сохраняется. Файлы доступны с nosniff и immutable-кэшем.

`manage.py cleanup` удаляет неиспользуемые медиа старше суток. При удалении работы/картинки сначала фиксируется транзакция, затем удаляются файлы. FileStorage изолирует хранение; реализация сейчас LocalFileStorage. Для S3 добавь новую реализацию и выбери её через конфигурацию, остальной код менять не нужно.

Для локального backend нужен постоянный каталог MEDIA_ROOT. В Compose добавлен media_data и необязательный профиль app с монтированием `/app/media` (сначала собери frontend). Обычный `docker compose up -d` по-прежнему запускает PostgreSQL и Mailpit. Для профиля app: `docker compose --profile app build`, затем `docker compose --profile app run --rm backend python -m alembic upgrade head` и `docker compose --profile app up -d`. На хостинге сохраняй том или замени FileStorage, настрой лимит тела прокси не меньше 5 МиБ плюс multipart-заголовки. MEDIA_ROOT не должен находиться в исходниках или общедоступном frontend/public.

## Найденные модули и принятые решения

Переиспользованы: models.py и app/models.py; app/api.py (коды, сессии, привязка), app/security.py, app/rate_limit.py, app/mail.py, app/cleanup.py, manage.py. Формат ошибок: code/message/field/errors, CSRF — JSON + X-Requested-With: devup. Исключение только для POST /api/admin/media (multipart с тем же заголовком и обязательной сессией).

Фронтенд: App.jsx/Layout, Header, components/UI.jsx (Dialog, Field, ErrorHint, Toast), выделенный PalettePanel, общий features/CodeStep.jsx, lib/api.js, AuthContext, кабинет. Модуль features/admin загружается через React.lazy. Для блокировки ухода с несохранёнными изменениями BrowserRouter заменён на createBrowserRouter/RouterProvider; клиентские маршруты сохранены. Прирост общего роутера не является кодом админки: админские страницы вынесены в отдельный chunk.

Расхождения с планом разрешены с сохранением существующих соглашений:

- services и portfolio_* уже существовали: миграции 0005–0006 расширяют их, сохраняют прежние поля и данные. Старые base_price/slug/storage_key поддерживаются для совместимости. Ширины прежних VARCHAR не сужаются; API валидирует новые пределы.
- У старых изображений media_id nullable; новые загрузки всегда используют media_files. Старые записи без настоящих медиа не превращаются в вымышленные картинки.
- Старые роли customer/admin сохраняются в схеме. Админский вход разрешён только manager; исторические customer учитываются как клиенты в списках и привязке.
- У старых менеджеров username не меняется автоматически. CHECK manager_username создан NOT VALID, чтобы сохранить такие строки и проверять все новые/изменяемые. Для старого менеджера без логина выполни create-manager с его существующей почтой: команда назначит выбранный username и новый пароль.
- Сиды услуг идемпотентны и не перезаписывают существующие записи. При downgrade строки услуг сохраняются, поскольку на них могут ссылаться старые заказы; добавленные колонки и ограничения откатываются.
- published_at хранит дату первой публикации. При отсутствии обложки используется первая картинка. Миниатюры не увеличивают маленькие исходники.
- Реальная загрузка файлов добавлена только в админское портфолио. Вложения клиентской заявки остаются макетом. Чат, аудит действий и редактирование клиентов не добавлены.

Проверки: pytest на отдельной devup_test; Vitest/React Testing Library; Playwright (админский вход, редакторы, preview, регрессия клиентов и адаптивность); применение/откат миграций до 0003 и повторное применение. Скриншоты: frontend/test-results/admin. Не запускай pytest и Playwright одновременно: они очищают одну тестовую БД. Все тестовые менеджеры создаются только в devup_test. Рабочие учётные записи автоматически не создаются.
