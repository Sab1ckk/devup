# PostgreSQL и миграции
npm run dev
Актуальные команды запуска, переменные среды, SMTP и тесты описаны в [README](../README.md).

Рабочее приложение использует синхронный SQLAlchemy и psycopg 3. Все изменения структуры проходят через Alembic:

```powershell
./.venv/Scripts/python.exe -m alembic upgrade head
```

- `0001`: исходная схема каталога, портфолио, отзывов и заказов.
- `0002`: авторизация, серверные сессии, заявки, контакты, коды, браузерные токены, история статусов, аудит привязки, лимиты, журнал почты и основа чата. Старые таблицы и данные не удаляются.
- `0003`: CHECK по допустимым видам блоков из первоначального общего каталога.

Основные модели прежних сущностей находятся в `models.py`, новые — в `app/models.py`. Alembic загружает оба набора метаданных. Дальнейшие изменения списка разрешённых блоков требуют соответствующей миграции CHECK.

Новые заявки используют `requests` и `request_*`, номера PostgreSQL Identity начинаются с 1001 и показываются как DEVUP-1001. Код привязки хешируется HMAC-SHA256, сессии и токены браузера — SHA-256, пароли — Argon2id. Активный код у заявки только один: это гарантирует частичный уникальный индекс. Привязка обновляет владельца только при `user_id IS NULL`. Проверка 2FA блокирует строку challenge; лимиты сериализуются advisory-lock PostgreSQL.

Для сохранения совместимости добавлена роль `client`, прежние роли customer/manager/admin не удалены. Новые аккаунты получают client. Старые записи orders не конвертируются в requests автоматически.

Проверки выполняются только на отдельной devup_test. На ней проверены применение, откат до 0001 и повторное применение новых миграций. Runtime не вызывает create_all и не меняет схему при запуске.
